## 1. T1~T3: gl-transitions 가져오기 (우선)

**프로젝트**: `https://github.com/gl-transitions/gl-transitions` — WebGL용 전환 셰이더 모음(수십~백 종 이상). 형식: GLSL 파일 하나가 `vec4 transition(vec2 uv)`를 정의하고 `getFromColor(uv)`, `getToColor(uv)`, `progress`(0→1), `ratio`(가로/세로)를 쓰며, 값은 `uniform`으로 선언하고 기본값을 `// = 값` 주석으로 적는다. 파일 머리에 `Author`/`License` 주석이 있는 규약이 있다(예시는 `License: MIT`).

**라이선스 규칙(엄격)**: 저장소 `LICENSE`를 확인하고, **각 파일 머리의 `License`가 MIT(또는 허용 목록)인 것만** 가져온다. 라이선스 표기가 없거나 MIT가 아닌 파일은 제외하고 `docs/dev/vendor/GLTRANSITIONS.md`에 제외 사유를 적는다. `NOTICE.md`에 "gl-transitions — MIT — 전환 셰이더(작가별 표기 유지)". **가져온 각 셰이더의 작가·라이선스 주석을 변환 결과에도 남긴다.**

### 변환 방식 (실행 시점이 아니라 개발 시점의 도구)
1. `xtask`에 명령 `cargo xtask gl-transitions <소스폴더>` 추가(새 크레이트 `naga` 의존, `glsl-in` 기능). 입력: 조사용으로 내려받은 gl-transitions 복사본(읽기 전용, D:). 출력: **커밋되는 생성 파일** `op-render/src/shaders/gl_transitions.wgsl` + `op-core` 쪽 카탈로그 조각 + 번역 TODO 목록.
2. 각 GLSL에 래퍼(`#version 450`, `getFromColor/getToColor` 구현, `progress/ratio` 상수)를 붙여 naga로 WGSL로 번역. 파싱·번역 실패 파일은 목록으로 남기고 건너뜀(손으로 고칠지 결정).
3. **파이프라인 1개 + 디스패처**: 각 전환을 `fn gl_<이름>(uv, progress, ratio, p: Params) -> vec4<f32>`로 만들고, `fs_tr_gl` 하나가 `index` 값으로 분기(전환 100개를 100개 파이프라인으로 만들지 않음). 셰이더 컴파일 시간·크기는 구현 때 측정해 한 파일이 너무 크면 20개씩 묶음.
4. **값**: `uniform float/int/bool/vec2/vec4` → 카탈로그 값(`vec2`는 두 값 x·y, `vec4 color`는 색 값). `// = 기본값` 주석에서 기본값·범위 추출. 값 개수는 전환당 최대 8개로 제한, 넘으면 처음 8개만.
5. **이름**: 파일명 → 영어 이름(카멜케이스 분리). **한국어 이름은 `ko.rs`에 사람이 직접**(생성 도구는 빠진 번역 목록을 만든다). 시험 `every_catalog_name_is_translated`가 막아 준다.

### 시험 (전 전환 공통, 헤드리스 GPU)
- `progress = 0` → 결과 = A 프레임(최대 오차 ≤ 2/255), `progress = 1` → B 프레임(≤ 2/255).
- `progress = 0.5` → NaN·무한대 없음, A·B 어느 쪽과도 완전히 같지 않음(전환이 실제로 작동).
- 목록 전체 반복 시험이 3분 안에 끝남. 시험은 `effect_previews.rs` 패턴.
- 실패한 변환 개수와 이유를 보고서에 적는다.

### 규모·순서
도구 + 변환 + 시험 **L**. 먼저 **인기 30종**(crosswarp, directionalwarp, doorway, dreamy, GridFlip, luminance_melt, morph, perlin, pinwheel, radial, ripple, rotate_scale_fade, squareswire, swap, undulatingBurnOut, windowblinds, Bounce, BowTieHorizontal, CircleCrop, cube, InvertedPageCurl, LinearBlur, heart, Hexagonalize 등 — **저장소 목록에서 실제 이름 확인**)로 파이프라인을 검증한 뒤 전체로 확장. 전환 목록 UI(효과 패널)에는 새 분류 `GL 전환`을 만들어 기존 것과 섞이지 않게 한다.

## 2. 효과 보강 (E 항목)
**주의**: 아래 "없는 것"은 사용자가 Premiere와 비교해 지적한 내용과 Premiere 효과 목록에 대한 **기억 기반 추정**이다. **구현 전에 사용자의 Premiere 화면 또는 공식 효과 목록과 대조**해 실제로 없는 것만 만든다(`catalog.rs`를 `grep`해 이미 있는 것은 제외).

| ID | 효과 | 우선 | 구현 메모 |
|---|---|---|---|
| E1 | **자동 색상·자동 레벨·자동 대비** | 높음 | 프레임 히스토그램(`scopes.wgsl` 재사용)으로 `levels`/`color_balance` 값을 계산해 적용. 한 번 분석하는 "자동" 버튼 + 값 직접 수정 가능 |
| E2 | **노이즈 감소**(공간 + 시간) | 높음 | 공간: 에지 보존 필터(양방향/중간값), 시간: 이전 프레임 혼합(프레임 기록 필요 → `Renderer`의 이전 프레임 캐시 설계가 선행) |
| E3 | 중간값(Median) | 중 | 3×3~7×7 중간값 패스 |
| E4 | **렌즈 블러**(보케) | 중 | 원형/다각형 커널 + 선택적 마스크(깊이 없이 마스크 기반) |
| E5 | 가비지 매트(4·8·16점) | 중 | `V5`(마스크)가 생기면 마스크로 대체. 그 전에는 폴리곤 점 N개 입력 효과 |
| E6 | 차이 매트 / 알파 조정 / 이미지 매트 키 | 중 | 키잉 `keying.wgsl`에 추가 |
| E7 | 에코 · 시간 에코 | 중 | 프레임 기록 필요(E2와 같은 기반) |
| E8 | 그림자/하이라이트 | 중 | 톤 마스크 기반 지역 보정 |
| E9 | 생성기류: 체커보드, 격자, 원, 타원, 4색 그라디언트, 번개 | 낮음 | 절차적 셰이더, 입력 없음(`ramp`·`fractal_noise` 패턴) |
| E10 | 색 변경(Change Color), 올 투 컬러 | 낮음 | `color_replace`와 겹치는지 확인 후 |
| E11 | 롤링 셔터 복구 | 낮음 | `03`의 안정기와 함께 검토 |
| E12 | 가장자리 거칠게, 난기류 변위, 베벨 알파 | 낮음 | 노이즈 기반 변위 패스 |
| E13 | 효과 프리셋 저장·불러오기 | 중 | `06` 참조(`op-core/src/presets.rs`가 있는지 확인) |

**공통 규칙**: 새 효과마다 ① 셰이더 `fs_*` ② `effects.rs` 분기 ③ `pipelines.rs` 등록 ④ `catalog.rs` ⑤ `ko.rs`/`es.rs` ⑥ `effect_previews.rs` 시험(입력 그림 → 효과 → 기대 변화: 예 "자동 레벨은 어두운 입력의 평균 밝기를 올린다", "노이즈 감소는 잡음 입력의 분산을 30 % 이상 줄인다") ⑦ 효과 제어창 자동 UI.

**프레임 기록이 필요한 효과(E2 시간 노이즈, E7)**: 현재 렌더러는 프레임 단위 무상태다. 필요하면 `Renderer`에 "이전 N프레임 결과 캐시"(시간 키)를 추가하되, **내보내기·재생·스크럽에서 같은 결과**가 나오게 시간 기준으로 계산(재생 순서 의존 금지). 이 설계가 정해질 때까지 E2 시간 모드·E7은 보류하고 공간 모드만 먼저.
