## 1. 프로젝트 사실 (코드로 확인한 것)

- **프로그램**: We edit. Rust(egui) 비선형 영상 편집기, 원 프로젝트(업스트림)를 개조. 라이선스 **GPL-3.0 이상**. 저장소 `https://github.com/icegyul/We-edit`(공개), 브랜치 `main`. 원 프로젝트 표기는 `NOTICE.md`·`LICENSE`가 책임지며 **지우지 않습니다**(GPL 의무).
- **작업 폴더**: `D:\## APP\We edit\` — `app\We edit.exe`(실행파일은 이것 하나), `source\`(git), `helper\`(faster-whisper 가상환경·모델), `toolchain\`(Rust), `generated\`.
- **크레이트** (`source\crates\`): `op-core`(데이터 모델·효과 카탈로그), `op-timeline`(편집 연산), `op-application`(Editor, 작업 큐, 내보내기), `op-ui`(egui 화면), `op-render`(wgpu 합성), `op-media`(FFmpeg 디코드·인코드), `op-audio`(실시간 믹서·소리 효과), `op-speech`, `op-silence`, `op-remix`, `op-mcp`(AI 도구). **새 크레이트 `op-master`**(01 명세)를 추가합니다.
- **시간 단위**: 1초 = 705,600,000 틱.
- **소리 처리 구조**: 클립 효과 → 트랙 → **마스터(`Sequence.master: Vec<Component>`, 볼륨 + 삽입 효과)**. 재생(`engine.rs`)과 내보내기(`export.rs`)가 **같은 `op_audio::Mixer`** 를 씁니다. 소리 효과는 `op-audio/src/effects.rs`의 `process()`가 효과 id로 분기하는 **실시간 블록 DSP**(상태 `FxState`)입니다. 내보내기는 영상 한 프레임마다 그 길이만큼(최대 8192프레임) 믹서에서 소리를 받아 인코더로 보냅니다.
- **영상 효과·전환**은 `op-render`의 WGSL 셰이더(`shaders/*.wgsl`) + `effects.rs`/`transitions.rs`의 분기 + `op-core/src/catalog.rs`의 `def!` 항목으로 구성됩니다.
- **FFmpeg**는 `ffmpeg-next`(feature: codec, format, software-scaling, software-resampling)로 연결, DLL 5개를 `app\`에 둡니다. `third_party\ffmpeg\bin\`의 BtbN GPL 빌드에는 avfilter와 `ffmpeg.exe`가 있지만 **개발·시험용 기준 도구로만 사용하고 배포하지 않습니다.**
- **사용자 PC**: i7-14700K(28스레드), RTX 3070 8GB, 램 192GB. 영상은 소니 4K 4:2:2 10비트 H.264(`C0039.MP4`는 소니 `rtmd` 데이터 스트림 포함). **C: 드라이브가 거의 가득 참**(시험 출력은 D:로).
- 작업 폴더의 `.git`은 **다른 세션이 동시에 고칠 수 있습니다**(2026-10-14에는 문구 정리 작업). 커밋은 `git commit -- <내 파일>`로, 빌드·시험은 필요하면 `git worktree`에서.

## 2. 반드시 지킬 규칙

1. **직접 만들기보다 가져오기**: 사용자 지시입니다. 가져올 수 있는 것(Rust 크레이트, GitHub 프로젝트, 이미 있는 FFmpeg 기능)을 먼저 쓰고, 없을 때만 직접 만듭니다. 가져온 것은 모두 `NOTICE.md`에 이름·라이선스·용도·고정 커밋을 적습니다.
2. **라이선스**: MIT/BSD/Apache-2.0/ISC/LGPL/GPL-3.0(이상)은 사용 가능. **GPL-2.0 전용은 불가**(frei0r, openfx-misc는 파일별 확인 전에는 사용 금지). **비상업 라이선스(CC BY-NC 등)는 불가**(Diff-MST 등). 모델 가중치 라이선스는 코드와 따로 확인.
3. **모델·큰 파일은 설치 파일에 넣지 않음**: 처음 쓸 때 내려받고, 커밋 고정 주소 + SHA-256 확인(기존 `sound_library.rs`, `whisper_models.rs`, `download.rs` 방식).
4. **되는지 확인하기 전에는 된다고 말하지 않음**: 시험(자동)과 확인(사람이 창에서 눌러 보거나 들어 봄)을 구분해서 보고. 소리 품질("녹음실급")은 **사람의 귀가 판정**하므로 "자동 시험 통과"를 "좋아졌다"로 말하지 않습니다.
5. **눌렀는데 반응이 없는 버튼 금지**: 모든 동작은 즉시 화면에 답(상태줄 메시지, 진행 표시, 오류 이유)을 냅니다. 긴 작업은 진행률과 취소를 가집니다.
6. **API 키·비밀은 소스·로그·프로젝트에 넣지 않음**(Windows 자격 증명 관리자만). **AudioMaster의 클라우드 AI 백엔드(OpenAI/Anthropic API 키 직접 호출)는 가져오지 않습니다** — AI는 우리 AI 패널(로그인 방식)과 MCP 도구로만 연결합니다.
7. **사용자 이메일을 커밋·문서에 넣지 않음**. git 신원은 저장소에 설정된 noreply 주소. 커밋 메시지 끝에 세션 지침이 주는 `Co-Authored-By` 줄을 붙임. 푸시는 사용자가 요청할 때만.
8. **사용자의 열려 있는 창을 건드리지 않음**: `--mcp` 시험, 마우스·키보드 자동화는 사용자의 We edit 창이 열려 있으면 금지. 시험은 `--portable` 복사본이나 헤드리스 시험으로. 시험용 창을 띄울 때는 사용자에게 알리고 끝나면 닫습니다. 설치는 `app\We edit.exe`가 잠겨 있지 않을 때 복사(잠겼으면 사용자에게 창을 닫아 달라고 요청).
9. **프로젝트 파일 호환**: 새 필드는 `#[serde(default)]`(+ 빈 값은 `skip_serializing_if`). 예전 `.wedalur`/`.opproj`가 계속 열려야 합니다.
10. **UI 문구는 한국어로 직접 작성**(영어 키 + `ko.rs` 번역). 새 카탈로그 항목은 **`op-ui/src/i18n/ko.rs`와 `es.rs` 둘 다**에 이름·분류·매개변수 이름·선택지를 넣지 않으면 `every_catalog_name_is_translated`/`korean_catalog_is_consistent` 시험이 실패합니다.
11. **디스크**: 시험·캐시·내보내기 출력은 D:에. 사용자의 다른 프로그램 임시 파일(`%TEMP%`의 Snapn, remotion 등)은 **건드리지 않음**. `rm -rf` 전에 링크(junction)가 없는지 확인.
12. **무음 실패 금지**: GPU·디코더·인코더 단계가 실패하면 "빈 데이터로 계속"이 아니라 재시도 후 **오류로 멈춥니다**(2026-10-14 내보내기 녹색 프레임 사건, 커밋 `1cc4acd`).

## 4. 작업 절차 (항목 하나마다)

1. 해당 명세를 읽고, 명세의 "현재 상태"가 지금 코드와 맞는지 `grep`으로 확인(코드가 바뀌었을 수 있음).
2. **시험부터 또는 함께**: 명세의 "합격 기준"을 자동 시험으로 만듭니다(헤드리스 GPU 시험 패턴: `op-render/tests/render.rs`, `op-application/tests/export_readback.rs`, 소리: `op-audio/src/effects.rs`의 `mod tests`).
3. 구현 → `cargo xtask cargo test -p <크레이트>` 통과.
4. 문서 갱신: `CHANGES.md`(한국어, 무엇을·어디 파일·시험 이름), `README.md` 표, `NOTICE.md`(가져온 것), AI 사용 설명(`op-ui/src/ai_panel.rs`의 프롬프트 줄), MCP 도구(`op-mcp/src/tools.rs`: 정의 + `run`(비어 있는 창) + `live`(열린 창) 분기 두 곳).
5. 릴리스 빌드(`cargo xtask build --release`, 약 4~6분), 새 빌드를 **시험용 실제 창에서 한 번 실행**해 확인, 설치, 커밋.
6. 사용자에게 **한국어로 짧게** 보고: 무엇을 했고, 무엇을 시험했고, **무엇을 직접 눌러 확인(청취)해야 하는지**.

### 명령 모음 (Git Bash)
```bash
cd "/d/## APP/We edit/source"
export RUSTUP_HOME="D:\\## APP\\We edit\\toolchain\\rustup" CARGO_HOME="D:\\## APP\\We edit\\toolchain\\cargo"
export PATH="/d/## APP/We edit/toolchain/cargo/bin:$PATH"
export TMP="D:\\## APP\\We edit\\scratch\\tmp" TEMP="D:\\## APP\\We edit\\scratch\\tmp"   # C: 보호
cargo xtask cargo test -p op-master -p op-audio -p op-core   # 시험
cargo xtask build --release                                  # 릴리스(원본: target\release\weedit.exe)
cp target/release/weedit.exe "../app/We edit.exe"       # 설치(창이 닫혀 있을 때)
```
주의: 긴 문자열이 든 패치는 heredoc 대신 **파일로 써서 실행**. PowerShell `Remove-Item`은 경로의 `##` 때문에 막힐 수 있음(bash `rm` 사용, 링크 주의).

## 7. 위험과 대비

| 위험 | 대비 |
|---|---|
| 가져온 코드의 라이선스 충돌 | 반입 전 `LICENSE` 확인 + NOTICE 기록. 불확실하면 쓰지 않음 |
| AudioMaster 품질이 기대에 못 미침(초기 프로젝트, 음악용 설정) | 프로파일 보정 + 교차 검증 시험 + 사용자 청취 체크리스트. 못 미치면 **끌 수 있게** 기본은 끔 |
| 모델 파일이 커서 느리거나 실패 | 처음 쓸 때만 내려받기 + 진행률 + SHA-256, 실패 시 이유와 수동 설치 안내 |
| 8GB VRAM 한계(RTX 3070) | 작은 모델부터, 프레임 단위 처리, 부족하면 CPU로 되돌리고 안내 |
| 새 소리 효과가 실시간 재생을 끊음 | 블록 처리 중 할당 금지(상태는 `FxState`에 미리 준비), 시험에서 블록당 시간 측정 |
| 내보내기 메모리(마스터링은 전체 믹스를 메모리에 올림) | 길이 상한과 임시 파일 처리(01 명세 7.2), 사용자에게 안내 |
| 사용자 창과 충돌 | 규칙 8 |
| 다른 세션과 같은 작업 폴더 충돌 | 규칙: 경로 한정 커밋, worktree 빌드 |
