# 조사 11: 프리미어 프로 비교 (없는 기능) + 깃허브에서 가져올 후보 (2026-10-14)

이 문서는 `08-조사-깃허브.md`를 보충합니다. 08은 라이선스 판정표이고, 이 문서는 **기능 단위**로 "프리미어에 있고 We edit에 없는 것"과 "그 기능을 어디서 가져올지"를 정리합니다.

## 0. 조사 방법과 한계
- We edit 쪽은 이 저장소의 코드를 직접 검색했습니다(`op-core/src/catalog.rs`, `op-ui/src/app/menus.rs`).
- 프리미어 쪽은 웹 검색 요약을 봤습니다. 검색 결과 대부분이 2020~2021년 기사여서 **Adobe 공식 도움말의 현재 목록과 대조해야 합니다.** 빠진 항목이 있을 수 있습니다.
- 깃허브 후보의 라이선스는 **패키지 정보와 검색 요약**에서 확인한 것입니다. 실제 반입 전에는 각 저장소의 `LICENSE` 파일을 열어 확인합니다. 확인하지 못한 항목은 "확인 필요"로 표시했습니다.

## 2. 깃허브에서 가져올 만한 후보

판정: **사용** = 확인 후 반입 가능, **참고** = 알고리즘만 보고 직접 구현, **보류** = 라이선스나 품질 확인 필요, **불가** = 라이선스 때문에 쓰지 않음.

| 후보 | 용도 (해당 기능) | 라이선스 (확인 수준) | 판정 | 비고 |
|---|---|---|---|---|
| **Gyroflow** (gyroflow/gyroflow) | 흔들림 보정 (Warp Stabilizer) | GPL-3.0 + 앱스토어 예외 (저장소 README 확인) | **사용 검토** | 소니 자이로 메타데이터 지원. 이 PC의 `C0039.MP4`에는 `rtmd` 데이터 스트림이 있음. `03` V1 |
| **vid.stab** (georgmartius/vid.stab) | 흔들림 보정(영상 분석) | **충돌**: 패키지 정보는 GPL-2+, 저장소 발췌는 LGPL-2.1+ | **보류** | LICENSE 파일 직접 확인 전 사용 금지. ffmpeg 빌드에 넣으려면 `--enable-gpl`이 필요하고, 우리 빌드는 avfilter를 배포하지 않음 |
| **PySceneDetect** (Breakthrough/PySceneDetect) | 장면 컷 찾기 (Scene Edit Detection) | **BSD-3-Clause** (scenedetect.com/copyright, 저작권 2014~2024 Brandon Castellano) | **참고** | 파이썬 코드는 복사하지 않고, 콘텐츠 검출(프레임 차이) 방식을 Rust로 새로 구현. `03` V3 |
| **AutoFlip** (Google) | 자동 리프레임 (Auto Reframe) | 상위 저장소 기준 Apache-2.0으로 표시됨. **직접 LICENSE 확인 필요** | **참고** | 무거운 MediaPipe 파이프라인. 구조와 아이디어만 참고 |
| **YuNet** (OpenCV Zoo) | 얼굴 검출 (자동 리프레임의 입력) | OpenCV Zoo 폴더 기준 **MIT**. 단 STMicroelectronics 사본에는 Apache-2.0 표시가 있어 **가중치별 확인 필요** | **사용 검토** | ONNX 파일로 작음. `07` 모델 관리자 경유 |
| **MediaPipe** (Google) | 얼굴 검출 대안 | Roboflow 카탈로그 기준 **Apache-2.0** | 보류 | 파이프라인 전체를 끌어오기엔 무거움. YuNet으로 충분한지 먼저 비교 |
| **lensfun** (lensfun/lensfun) | 렌즈 왜곡 보정 프로필 (소니 렌즈) | 라이브러리 **LGPL-3.0**. 렌즈 데이터는 **CC-BY-SA**로 패키징됨 | **보류** | 소니 최신 렌즈가 빠진 경우가 있음(pixls.us 포럼). 데이터 라이선스(CC-BY-SA)의 공유 의무를 검토해야 함 |
| **OpenColorIO** (AcademySoftwareFoundation/OpenColorIO) | 색 공간 관리(LUT·색 변환) | **BSD-3-Clause** (공식 문서) | 보류 | Rust 바인딩이 확인되지 않음(C++ 감싸기 필요). Color Match 자체는 OCIO가 아님 |
| **Color Match** (참조 색 맞추기) | Color Match | **저장소 후보를 찾지 못함** | 직접 구현 | 널리 알려진 색 이동(Reinhard, 평균·표준편차를 맞춤) 방식. 코드 복사 없이 구현. `04` E14 |
| 자동 덕킹 | Auto Ducking | — | 직접 구현 | 음성 감지(`op-silence` 신경망)와 볼륨 키프레임으로 충분. `02` A7 |

**확인 못 한 것 (솔직하게)**
- Color Match, Auto Color, 다중 카메라(Multicam)에 대해서는 **쓸 만한 깃허브 프로젝트를 찾지 못했습니다.** 검색을 더 해야 합니다.
- MediaPipe, AutoFlip, lensfun, vid.stab은 **LICENSE 파일을 직접 열어 보지 못했습니다.**

## 3. 우선순위 (사용자 체감 × 라이선스 안전)

| 순서 | 기능 | 방법 | 이유 |
|---|---|---|---|
| 1 | **자동 덕킹** | 직접 구현 (`02` A7) | 라이선스 문제 없음. 대화 영상 체감이 가장 큼 |
| 2 | **장면 컷 찾기** | PySceneDetect 방식 직접 구현 (`03` V3) | BSD-3 알고리즘 참고. 구현 부담 적음 |
| 3 | **Auto Color / Color Match** | 직접 구현 (`04` E1, E14) | 공개 알고리즘. 깃허브 의존 없음 |
| 4 | **자동 리프레임** | YuNet(ONNX) + 직접 평활화 (`03` V8) | 얼굴 검출 모델의 라이선스를 가중치 단위로 확인 후 |
| 5 | **흔들림 보정** | Gyroflow 검토 → 안 되면 직접 광학 흐름 (`03` V1) | 소니 메타데이터가 있으면 품질이 높음. GPL 호환 |
| 6 | 모프 컷 · 속도 곡선 · 다중 카메라 | 직접 구현 (`03` V2·V4, `06` U5) | 기존 구조에 맞춰야 함 |
| 7 | 렌즈 프로필 | lensfun 보류 | 데이터 라이선스(CC-BY-SA) 검토 필요 |
