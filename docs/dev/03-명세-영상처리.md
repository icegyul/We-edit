# SPEC-03 영상 처리: 안정화 · 모프 컷 · 장면 감지 · 시간 다시 매핑 · 마스크 · 배경 제거 · 자동 리프레임

사용자의 영상은 **소니 카메라 4K 4:2:2 10비트 H.264, 말하는 사람 중심의 대화형 유튜브**(컷이 매우 많음: 2026-10-14 프로젝트 기준 클립 386개). 그래서 "점프 컷을 자연스럽게", "손떨림 보정", "배경 정리", "쇼츠용 세로 리프레임"이 체감이 큽니다.

## 0. 현재 상태 (코드로 확인)
- 클립 속도는 **고정값**(`Clip.speed`, `reverse`, `hold`) — 시간 다시 매핑(속도 곡선) 없음. `Clip.speed.is_normal()`일 때만 볼륨 선 표시.
- **마스크 없음**(`op-core` 모델에 `Mask` 구조 없음). 키잉(`ultra_key`, `color_key`, `luma_key`)·`track_matte`는 있음. 색 보정은 `lumetri` + 색 노드(`colorgraph.rs`).
- 장면 감지 코드 없음. 안정기 없음(`camera_shake`는 흔드는 효과). 보간 없음.
- 머신러닝 실행 기반은 `op-speech`의 **candle**(Whisper)뿐. ONNX 런타임 없음 → `07`.
- 쇼츠 기능 `op-application/src/shorts.rs` 존재(세로 변환 관련) — 구현 전에 읽어 재사용 범위 확인.

## 2. V1 영상 안정화
**현황 근거**: 사용자 클립 `C0039.MP4`는 소니 XAVC이며 **`rtmd`(Real-Time MetaData) 데이터 스트림이 있다**(`ffprobe`로 확인). 소니 카메라는 설정에 따라 이 스트림에 **자이로·가속도** 값을 기록한다. Gyroflow는 소니(a7S III, FX3, FX6, FX9, ZV-E10, a6700 등)의 이 메타데이터를 읽어 안정화한다.
**Gyroflow**: `https://github.com/gyroflow/gyroflow`, 라이선스 **GPL-3.0 + 앱스토어 예외**(우리와 호환), Rust. README에 `gyroflow_core`(`src/core`)가 "외부 의존성 없는 별도 라이브러리(Qt·ffmpeg·OpenCV 없음)"라고 적혀 있다.

### 2.1 조사 단계 (구현 전 반드시, 1일)
1. 읽기 전용으로 내려받아(`D:` 임시 폴더, 실행·빌드 금지) `src/core/Cargo.toml`의 의존성·크레이트 이름·공개 API(자이로 파서, 안정화 알고리즘, 렌즈 보정)를 확인.
2. **사용자의 `C0039.MP4`에 자이로 값이 실제로 들어 있는지** 확인(Gyroflow 공개 앱으로 열어 "자이로 데이터 있음" 표시 확인, 또는 core의 telemetry 파서로 읽기). 값이 없으면(설정 꺼짐) 아래 2.3의 광학 흐름 방식만 쓴다.
3. core를 크레이트로 쓸 수 있는지(git 의존성 / 필요한 파일 반입) 결정하고 결과를 `docs/dev/vendor/GYROFLOW.md`에 기록. 반입 시 `NOTICE.md`·헤더 규칙은 `01` 2장과 같다.

### 2.2 구조 (자이로가 있을 때)
- **분석 작업**(`remix.rs` 패턴, 백그라운드·진행·취소): 클립의 원본 파일에서 자이로 → 프레임별 카메라 회전 궤적 → 평활화(`smoothness`) → 프레임별 보정 변환(회전 + 확대) 계산 → 캐시(`helper\cache\stabilize\<파일해시>.bin` 또는 `MediaCache`, **C: 아님**).
- **효과** `op.video.stabilizer`(새 WGSL 패스): 값 `smoothness`(0~100), `crop`(자동 확대 여백), `method`(자이로/영상 분석), `status`(읽기 전용: 분석 전/중/완료). 렌더 시 캐시의 프레임별 변환을 읽어 한 패스로 워프(모서리는 확대로 가림). 분석 전이면 효과는 통과 + 제어창에 "분석하기" 버튼.
- 분석 결과는 `원본 파일 + 구간`에 묶인다(클립을 잘라도 재사용).

### 2.3 자이로가 없을 때 (영상 분석 방식, 직접 구현)
- 축소 프레임(예: 480×270 밝기)에서 프레임 간 **전역 움직임**(이동 + 작은 회전·확대)을 추정: 블록 위상 상관 또는 희소 특징 추적(Lucas–Kanade) → 궤적 평활화(가우시안/칼만) → 같은 `op.video.stabilizer` 렌더 경로. 롤링 셔터는 1차 범위 밖.
- FFmpeg `vidstab`는 **쓰지 않는다**(우리 빌드는 avfilter 미연결, `ffmpeg.exe` 미배포).

### 2.4 시험·합격
- 합성: 알려진 흔들림(사인 이동 ±8 px)을 건 영상 → 안정화 후 프레임 간 잔여 이동의 표준편차가 입력의 **30 % 이하**.
- 정지 영상(흔들림 0) → 출력 = 입력(±1 화소), 불필요한 확대 없음.
- 캐시: 같은 클립 두 번째 분석은 즉시(해시 적중), 파일이 바뀌면 무효.
- 사용자 확인: 손으로 든 소니 클립으로 전/후 비교(멀미·젤리 현상 여부).

## 3. V2 모프 컷 (점프 컷 부드럽게)
Premiere의 모프 컷처럼 같은 사람의 이어진 컷 사이를 자연스럽게 잇는다. **현실적인 기대**: 말하는 얼굴이 크게 움직이면 흔적이 남는다 — 1단계는 "빠른 광학 흐름 워프 디졸브", 2단계는 AI 보간.
- **전환 효과 `op.tr.morph_cut`**(컷 위에 `add_dissolve_at_cut`처럼 놓음): 값 `duration`(기본 0.25초), `mode`(흐름/AI), `face_priority`(얼굴 영역 가중, 2단계).
- **1단계**(모델 없음): 컷 앞 마지막 프레임 A와 뒤 첫 프레임 B 사이의 **양방향 광학 흐름**(GPU 컴퓨트, 피라미드 Horn–Schunck 또는 DIS 흐름, 작은 해상도에서 계산 후 확대)을 컷마다 한 번 계산해 캐시 → 프레임마다 `out = mix(warp(A, t·F_ab), warp(B, −(1−t)·F_ba), t)`. 전환 렌더는 `op-render/src/transitions.rs`, 셰이더 `transitions.wgsl`.
- **2단계**: RIFE(MIT 코드)를 ONNX로(`07`). `rife-ncnn-vulkan`은 MIT이고 Windows 실행 파일이 있으나 **모델 파일 라이선스가 저장소에 명시되지 않아** 가중치 라이선스를 확인하기 전에는 배포하지 않는다.
- **시험**: 합성 두 장면(같은 물체가 조금 이동) → 중간 프레임에서 물체 위치가 A와 B의 중간 ±2 화소, 이중상(고스트) 에너지가 단순 디졸브의 50 % 이하. 핸들(여유 프레임)이 없는 컷은 거부 메시지.

## 4. V3 장면 감지
- 알고리즘은 PySceneDetect(BSD-3)의 **ContentDetector**와 같은 방식을 Rust로 새로 쓴다(코드 복사 없음): 160×90으로 줄인 프레임의 HSV 평균 절대 차이가 임계값(시작값 27, 최소 장면 길이 15프레임)을 넘으면 컷. `op-media`의 디코더로 저해상도 프레임만 읽는다.
- **결과 사용**: ① 클립 우클릭 `장면 감지로 자르기`(모든 컷 지점에 면도날, 한 번의 되돌리기) ② 마커로만 표시 ③ MCP `detect_scenes {clip_id, threshold?}`.
- **시험**: 합성 영상(색이 바뀌는 5장면)에서 컷 지점 정확도 ±1프레임, 점진적 밝기 변화에는 거짓 컷 없음.

## 5. V4 시간 다시 매핑
- 모델: `Clip.time_remap: Option<Vec<RemapKey>>`(`serde(default)`) — 시퀀스 시간 → 원본 시간 키프레임(선형/베지어). 없으면 기존 `speed` 동작 그대로.
- UI: 클립에 **속도 선**(볼륨 선과 같은 조작: 점 추가·드래그·우클릭 삭제, `timeline.rs`의 `volume_*` 패턴), 램프(점 사이 가속·감속) 표시, 소리는 해당 구간에서 피치 유지 여부 선택.
- 렌더: `plan.rs`가 프레임별 원본 시간을 키프레임으로 계산(기존 `LayerSource::Media{time}`에 이미 원본 시간이 실림). 슬로모션은 프레임 블렌딩 → (선택) RIFE.
- 시험: 2배→0.5배 램프에서 원본 프레임 번호가 단조 증가·기대 곡선 ±0.5프레임, 되돌리기, 옛 프로젝트 호환.

## 6. V5·V6 마스크와 추적
- **V5**: `Mask { points: Vec<BezierPoint>, feather, expansion, opacity, invert, keys }`를 **어떤 효과에도** 붙일 수 있게(Premiere 방식: 효과 제어창의 마스크 아이콘). 렌더: 마스크를 R8 텍스처로 래스터화 → `render.rs`의 효과 적용 함수가 `mix(원본, 효과결과, 마스크)`. 모니터에서 점 드래그 편집. 키프레임으로 이동·변형.
- **V6**: SAM 2(`facebookresearch/sam2`, 코드 Apache-2.0). **주의**: 가중치 라이선스는 Hugging Face 카드에는 Apache-2.0으로 되어 있으나 Hiera 백본이 CC BY-NC라는 보고가 있어 **배포 전 Meta 공식 문서로 확인**(GPL 앱은 추가 제한을 둘 수 없음). 영상 추적(비디오 예측기)의 ONNX 변환은 확인되지 않음 → 현실적 경로는 **`helper\` 파이썬 환경(Whisper와 같은 방식)에서 PyTorch로 실행**하고 결과 마스크 시퀀스를 캐시. 8GB VRAM에는 tiny/small 모델부터.
- 시험: 합성 원 이동 영상에서 추적 마스크 IoU ≥ 0.9, 마스크 편집 되돌리기.

## 7. V7 배경 제거 (말하는 사람)
- 후보: **RobustVideoMatting**(GPL-3.0, ONNX 모델 제공 — 시간적으로 안정적인 영상 매팅, 실시간급), **BiRefNet**(MIT, 프레임별 고정밀, 느림). 우리 앱이 GPL-3.0-or-later이므로 RVM의 GPL-3.0 코드·가중치는 호환(출처 표기 필수)이다. **사용자 영상(말하는 사람)에는 RVM 우선**, 정지 이미지·고정밀은 BiRefNet.
- 효과 `op.video.remove_background`: 값 `model`, `edge_feather`, `despill`, `output`(알파 / 합성 / 흑백 마스크). 첫 사용 시 모델 내려받기(`07`), 분석 결과는 알파 시퀀스로 **캐시**(클립별, D:).
- 시험: 합성(단색 배경 + 움직이는 사각형)에서 알파 IoU ≥ 0.95, 첫 프레임부터 끝까지 깜빡임(프레임 간 알파 변화 평균) 기준 이하.

## 8. V8 자동 리프레임
- 얼굴 검출 ONNX(YuNet MIT 또는 BlazeFace Apache-2.0, `07`) → 프레임별 얼굴 중심 → **평활화(속도 제한·데드존)** → 클립 `Motion`의 위치·크기 키프레임으로 변환(사용자가 고칠 수 있음). 대상 비율 선택(9:16, 1:1, 4:5). `shorts.rs`와 충돌하지 않게 기존 흐름에 "자동 리프레임" 단계로 연결.
- 시험: 합성(좌우로 움직이는 얼굴 그림)에서 크롭 창이 얼굴 중심 ±10 % 이내, 급격한 점프 없음(프레임당 이동 상한).

## 9. V9 Lumetri 보강
구현 전에 현재 `lumetri.wgsl`·`video.lumetri` 값 목록을 확인해 **빠진 것만** 추가(HSL 보조, 색상 대 채도/색상 대 휘도 곡선, 비네트는 이미 별도 효과). 사용자가 Premiere와 비교해 지적한 항목을 우선.

## 10. 공통 규칙
- 모든 분석·AI 작업은 `remix.rs` 패턴(백그라운드·진행·취소·결과 캐시), 결과 캐시는 **D: 쪽**(설정으로 변경 가능), 캐시 키는 파일 해시 + 구간 + 설정.
- 분석이 끝나지 않은 효과는 **원본 통과 + 제어창에 상태 표시**(눌러도 반응 없는 버튼 금지).
- 새 카탈로그 항목은 `ko.rs`/`es.rs` 필수, 효과 미리보기 시험(`effect_previews.rs`) 포함.
