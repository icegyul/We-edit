# SPEC-07 AI 모델 기반 (모델 관리자 · ONNX 실행 · 작업 틀)

마스크 추적·배경 제거·음성 향상·보간·얼굴 검출이 모두 **머신러닝 모델**을 필요로 합니다. 모델마다 따로 만들지 않고 **공통 기반 한 벌**을 만들어 `03`·`02`의 항목이 올라타게 합니다. (소리 마스터링 `01`은 모델이 필요 없습니다 — 일반 DSP + 규칙/LLM 계획.)

## 0. 현재 상태
- ML 실행은 `op-speech`의 **candle 0.11**(Whisper)과 `helper\`의 **파이썬 faster-whisper**(문장 편집·자막). ONNX 런타임 없음.
- 모델 내려받기 패턴은 있음: `whisper_models.rs`(Hugging Face 저장소에서 `helper\models`로 내려받기, 진행률), `sound_library.rs`(커밋 고정 + SHA-256), `download.rs`.
- 사용자 PC: RTX 3070 8 GB VRAM, 램 192 GB. 모델은 **작은 것부터**. **C: 드라이브는 거의 가득** → 모델 저장은 `helper\models`(D:) 기본.

## 1. 구성

### 1.1 ONNX 실행 `crates/op-ml` (새 크레이트)
- `ort`(pykeio, ONNX Runtime의 Rust 래퍼, 라이선스 Apache-2.0 또는 MIT로 보고됨 — **의존성 추가 전 `crates.io`/저장소에서 직접 확인**) + ONNX Runtime 자체(MIT).
- Windows에서 GPU는 **DirectML 실행 공급자**(CUDA 도구 설치 불필요). 배포 파일: `onnxruntime.dll`, `DirectML.dll`을 `app\`의 FFmpeg DLL 옆에 둔다(규칙: 실행 파일 하나 + DLL은 허용). `ort`는 `load-dynamic` 방식으로 우리가 둔 DLL을 읽게 한다. **`ort` API는 자주 바뀌므로 구현 전 최신 문서를 읽고 시작.**
- 공개 API(안): `Session::load(model_path, Device::Auto|Gpu|Cpu)`, `run(inputs) -> outputs`, 오류 시 **CPU로 되돌리고 알림**(조용히 느려지지 않게 "GPU를 쓸 수 없어 CPU로 처리합니다" 표시). 입력 텐서 변환 도우미(`VideoFrame` YUV → RGB f32 NCHW, 알파 시퀀스 출력).
- 대안 검토: `candle-onnx`는 연산 지원이 부분적이라 1순위로 쓰지 않는다. 필요한 모델이 `ort`로 안 돌면 그때 candle 포팅 또는 파이썬 도우미.

### 1.2 모델 관리자 `op-application/src/models.rs`
```rust
pub struct ModelInfo {
    pub id: &'static str,          // "rvm-mobilenetv3"
    pub label: &'static str,       // 화면 표시(한국어)
    pub task: Task,                // Matting, Segmentation, Interpolation, FaceDetect, SpeechEnhance …
    pub url: &'static str,         // 커밋 고정 주소(HF resolve/<커밋>/파일)
    pub sha256: &'static str,
    pub megabytes: u32,
    pub license: &'static str,     // "MIT" / "Apache-2.0" / "GPL-3.0" …
    pub license_url: &'static str, // 가중치 라이선스 근거 페이지
    pub min_vram_mb: u32,
}
```
- 저장 위치 `helper\models\onnx\<id>\`(설정에서 변경 가능), **처음 쓸 때만** 내려받기: 대화상자에 이름·크기·**라이선스와 근거 링크** 표시 → 사용자 확인 → 진행률·취소 → SHA-256 확인 → 실패 시 이유와 수동 설치 안내(`whisper_models.rs` 패턴).
- **라이선스 관문**: 레지스트리에 `license`가 비어 있거나 허용 목록(MIT, Apache-2.0, BSD-*, ISC, LGPL, GPL-3.0)에 없으면 **목록에 넣지 않는다**(GPL 앱은 비상업·추가 제한 가중치를 배포할 수 없음). 가중치 라이선스는 **코드 라이선스와 따로** `license_url`로 확인해 기록.
- 모델 관리 화면(환경 설정 > AI 구성요소): 설치된 모델 크기·삭제·다시 받기·저장 위치.

### 1.3 AI 작업 틀 `AiJob`
`remix.rs`의 작업 패턴 일반화: 백그라운드 스레드, 진행률(0~1 + 단계 문자열), 취소, 결과 캐시. **캐시 키 = 원본 파일 지문 + 구간 + 모델 id + 설정**, 위치 `helper\cache\ai\`(D:). 결과 형식: 알파/마스크 시퀀스(압축 R8 프레임 묶음), 흐름장, 좌표 키프레임 등 작업별. 실패는 **빈 결과로 계속하지 않고 오류로 알림**(`00` 규칙 12).
- 효과가 AI 결과를 쓰는데 아직 없으면: 원본 통과 + 제어창에 "분석하기" 상태 표시.

### 1.4 파이썬 도우미 경로(선택)
SAM 2의 비디오 추적처럼 ONNX 변환이 확인되지 않은 모델은 **`helper\` 파이썬 환경**(Whisper와 같은 방식, `sentences.rs`의 `run_helper` + JSON 줄 입출력)에서 PyTorch로 실행. 설치는 "고급 AI 구성요소" 버튼으로 사용자가 선택(PyTorch는 수 GB). 기본 설치에는 넣지 않는다.

## 3. 시험
- `registry_is_sane`: 모든 모델에 `sha256`(64 hex), `license`(허용 목록), `license_url`, 크기 > 0.
- `download_verifies_hash`: 로컬 HTTP 서버(시험용 작은 파일)로 내려받기 → 해시 불일치 시 파일 삭제·오류, 취소 시 부분 파일 삭제, 이어받기 없음(단순).
- `ort_smoke`: 시험 코드가 만든 아주 작은 ONNX 모델(항등/덧셈)을 로드·실행해 결과 확인 → GPU 불가 환경에서 CPU 대체와 알림이 나오는지.
- `ai_job_cache`: 같은 입력 두 번째 실행은 캐시 적중, 설정이 다르면 미적중, 취소 시 결과 없음.
- 각 모델 연동 시험은 해당 항목 명세(`03` 등)에 있다.

## 4. 순서
① `op-ml` + `ort_smoke` ② 모델 관리자 + `registry_is_sane`/`download_verifies_hash` ③ `AiJob` ④ **RVM 한 모델을 끝까지**(`03` V7: 받기 → 실행 → 효과 → 캐시 → 내보내기 일치) ⑤ 나머지 모델은 라이선스 확인이 끝난 것부터 하나씩.
각 단계 끝에 설치·커밋·사용자 확인(특히 ⑤는 **라이선스 근거 링크를 보고서에 첨부**).
